# Automade Website Studio

웹사이트를 설계하고 **「사이트 만들고 열기 ↗」 버튼 한 번으로 실제 사이트를 실행**하는 제작 도구입니다. 기존 8개 도구·캔버스·속성 패널을 유지하면서 조직·팀·여러 사이트·환경 관리까지 확장했습니다. 편집기·미리보기·생성 결과에 같은 React 런타임을 사용합니다.

## 시작

Windows에서 루트의 `start-site.cmd`를 더블 클릭하세요. Node.js 22.16 이상이 필요합니다. 실행기는 PATH와 사용자 설치 폴더를 확인하고, 의존성 설치·빌드·헬스 체크 후 브라우저를 엽니다. 첫 설치에는 인터넷이 필요합니다. 실행 주소는 창에 표시하며 정상 서버가 있으면 재사용합니다.

개발 시 `npm ci`, `npm run dev` 후 **http://127.0.0.1:5173/** 에 접속하세요. `dev:ui`는 UI 개발 전용이며 저장·생성 API를 제공하지 않습니다.

## 제작

1. 회사 소개·포트폴리오·랜딩·대시보드·빈 프로젝트로 시작합니다. 설명 기반 구성은 기본 템플릿을 선택하며, 외부 생성 API를 설정하면 해당 공급자를 사용합니다.
2. 블록·페이지·레이어·이미지·프로젝트 도구로 구성합니다. 클릭은 반응형 흐름, 끌어 놓기는 자유 배치입니다.
3. 내용·폼 필드·표 열·탭·차트·테마·화면별 표시·버튼 동작을 지정합니다. 크기 조절·확대·스냅 안내선·다중 선택·그룹·잠금·정렬·실행 취소를 지원합니다.
4. PC·태블릿·모바일과 동작 미리보기, 품질 패널로 확인합니다.
5. **「사이트 만들고 열기 ↗」** 를 누르면 검사 → 소스 생성 → 빌드 → 데이터 스냅샷 → 서버 실행 → 준비 확인 → 새 탭 열기가 이어집니다. 팝업 차단 시 결과 링크를 사용하세요.

폼은 SQLite에 실제 저장됩니다. 표는 검색·형식별 정렬·페이지·행 편집·CSV를 지원합니다. 문의는 운영 패널에서 조회합니다. 미리보기는 실제 데이터를 저장하지 않습니다.

## 저장과 복구

IndexedDB와 서버 SQLite에 자동 저장합니다. 저장 완료 표시를 확인하세요. 원본 가져오기·내보내기·복제·이전 저장본 복구를 제공합니다. 기존 localStorage 원본은 보존하며 버전 2로 이전합니다. 손상·충돌은 오류로 표시하고 덮어쓰지 않습니다.

## 결과

`exports/<작업ID>/`에 `start-site.cmd`, `output/dist`, React/TypeScript 소스, 편집 원본, 독립 API 서버, SQLite 데이터, 품질 보고서와 빌드 설정을 만듭니다. 생성한 OS·아키텍처의 Node 실행파일도 포함합니다. 생성 폴더의 `start-site.cmd`는 추가 npm 설치 없이 실행합니다. 다른 OS에서는 해당 OS의 Node22.16 이상으로 `output`의 `npm start`를 실행하세요.

ZIP 다운로드에는 편집 원본·실행파일·Docker 설정을 포함하며 실제 운영 DB는 제외합니다. 프로젝트별 실제 데이터는 `.data/sites/<프로젝트ID>/site.sqlite`에서 이어집니다. 재생성은 이 데이터를 보존하고 이전 릴리스의 쓰기를 차단합니다. 운영 패널에서 이전 결과를 다시 실행하면 최신 저장소를 읽는 읽기 전용 사이트가 됩니다. 별도 폴더의 독립 실행은 해당 결과의 스냅샷 또는 지정한 SITE_DATA_FILE을 사용하므로 운영 데이터 이동은 온라인 백업·복구로 수행하세요.

## 추가 제작·운영 기능

목적별 시작 안내와 초안 검토, 검색·즐겨찾기·블록 조합, 계층 이동·다중 선택·한 번에 실행 취소, 테마 상속·기기별 예외, 직접 텍스트 편집, 반복 콘텐츠 CMS·다국어·페이지 SEO, 이미지 최적화·교체·원본 복구를 지원합니다. 표는 열 규칙·CSV 매핑·수정 충돌·변경 이력, 차트는 실제 표 연결을 제공합니다. 품질 오류는 해당 필드로 이동하고 안전한 수정도 검토 후 적용합니다.

운영 패널에는 영속 생성 작업, 사이트별 문의 검색·상태·메모·CSV·마스킹, 운영 데이터 백업·복구, 보존 후보 검토·가역 격리, 회원·역할·초대·변경 승인, 외부 연결·알림 재시도, 상품·주문·부분 환불, 예약·정원, 로컬 플랜·사용량이 있습니다. 공개 배포 연결은 실제 공개 릴리스·버전·패키지 해시를 확인해야 성공으로 표시합니다.

## 확장 기능

조직과 작업공간·사이트·검수/운영 환경, 제작자 계정과 세부 권한, 공유 컴포넌트·브랜드·업종 팩, 파일 자산 저장소, 타입 CMS·검토/예약 발행·지역 언어, 외부 데이터 바인딩과 자동화, scoped API·서명 웹훅, 충돌 검토와 협업 상태, 예약 대기와 주문 후처리를 기존 메뉴에서 사용합니다. 운영은 환경별 DB·릴리스, 별도 worker 프로세스·영속 작업 큐·사용량 한도, 검증한 DB 이전·복원 후 거래 대사로 이어집니다.

새 블록·팩은 선언형 등록 및 버전/무결성 검사로 관리합니다. `npm run extension:check -- <manifest.json>`으로 확장 계약을 검사합니다. [전체 E01~E32 구현과 검증](docs/expansion-implementation.md) · [확장 서버 계약](docs/expansion-backend.md) · [확장 SDK](docs/extension-sdk.md)를 참고하세요.

## 운영 범위

기본 `APP_MODE=local`은 **127.0.0.1 소유자 도구**입니다. `APP_MODE=managed`는 정확한 HTTPS 공개 origin·제작자 로그인·서버 권한 검사를 요구하며 사설 IP나 loopback으로 소유자 권한을 얻지 못합니다. 두 모드 모두 CSRF·Host·Origin 검사를 적용합니다. 생성 사이트의 방문자 계정은 제작자 계정과 별도입니다. 무설정 상태는 설명 기반 로컬 템플릿이며 외부 AI에는 전송 범위·요청·예상 비용 한도를 적용합니다.

로컬 비밀 저장소 키는 최초 실행에 `.data/keys/expansion.key`로 생성합니다. 프로젝트/ZIP/운영 DB 이전에 포함하지 않으므로 DB와 함께 별도의 안전한 장소에 백업해야 합니다. 키가 유실되면 저장한 연결 비밀값을 복호화할 수 없습니다. 관리형은 `EXPANSION_SECRET_KEY`를 운영 비밀 관리로 설정합니다.

외부 AI·결제·메일·공개 운영은 공급자 선정·비밀 환경 설정과 실환경 검증이 필요합니다. 연결은 문서화된 공급자 게이트웨이 계약을 사용하며 미설정 연동을 성공으로 표시하지 않습니다.
