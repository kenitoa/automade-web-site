# 전체 고도화 구현 계획

2026-10-07. 사용자가 앞서 작성한 전체 기획안의 반영을 요청했다. 공개 배포 대상과 외부 AI·메일/CRM·결제 공급자는 미정이며, 로컬 완성과 실제 연결 설정을 먼저 구현한다. 미설정 연동을 완료·발송·결제로 표시하지 않는다.

## 목적과 보존할 구조

상단 프로젝트 바, 좌측 8개 도구, 중앙 캔버스, 우측 속성, 원클릭 로컬 생성, 공통 사이트 런타임, 원본/소스/독립 실행 결과물을 유지한다. 제작 경험, 사이트 품질, 저장/복구, 실제 운영을 이어준다. 기존 데이터와 사용자의 변경을 보존한다.

## 컴포넌트와 데이터 흐름

편집 명령 → 검증된 additive schemaVersion2 Project → IndexedDB/SQLite 원본과 백업 → 공통 렌더링 → 영속 생성 작업 → 독립 산출물 → 로컬 실행 또는 설정된 공개 배포 → 사이트별 영속 운영 DB → 문의/연동/주문/예약 처리와 감사 기록.

제작 플랫폼 계정, 사이트 관리자/운영자, 방문자 계정을 권한 범위로 구분한다. 편집 버전·생성 릴리스·운영 데이터·공개 배포는 독립적인 상태로 기록한다. 디자인 롤백은 최신 운영 데이터를 유지한다.

## 구현 순서

1. 기존 타입/린트/32개 단위·통합 테스트를 기준으로 확인한다.
2. 데이터 보존·활성 버전·영속 작업·백업을 구현한다.
3. domain/runtime, editor, platform 모듈을 소유 파일을 분리해 병렬 구현한다.
4. API/타입/생성 산출물/사이트 운영을 통합한다.
5. 타입·린트·테스트·프로덕션 빌드, Chromium E2E, 독립 산출물 검증을 실행한다.
6. 요구사항별 구현/검증/미설정·미검증을 기록하고 문서를 갱신한다.

## 위험 및 복구

운영 데이터가 존재한다고 가정한다. migration0001은 수정하지 않고 새 번호를 적용한다. 초기화·삭제·외부 게시·실거래는 수행하지 않는다. 기존 데이터의 정규 운영 저장소로의 이전은 백업과 검증 뒤 진행하고 원본 파일을 남긴다. 저장본 복원은 복원 직전 온라인 백업을 만든 뒤 사이트 쓰기를 중지하고 수행하며, 실패 시 이전 파일로 복구한다. 새 버전 생성 실패는 기존 활성 사이트를 유지한다. 공개 모드는 인증·권한·HTTPS 설정이 충족되어야 활성화한다.

## 검증 및 완료 범위

기존 호환성과 외부 동작을 테스트한다. 재생성 중 제출/재시작/멱등성/과거 실행/백업 복원, 권한 우회/CSRF/SSRF/웹훅 중복·역순/재고·예약 경합을 포함한다. 실제 외부 공급자·배포 대상은 미정이므로 설정/연결 동작과 로컬 계약 테스트를 구현하고 외부 성공을 주장하지 않는다. 실제 휴대폰·스크린리더·외부 사용자 성과는 별도 미검증으로 표시한다.
