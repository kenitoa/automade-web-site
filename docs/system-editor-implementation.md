# 시스템 고도화 편집기 구현과 검증 경계

기존 블록·페이지·레이어·자산·프로젝트·품질·출력·운영의 8개 메뉴와 캔버스/Inspector를 유지한다. 새 관리 기능은 기존 운영 화면의 지연 로딩 패널로 제공한다. 배포 대상·도메인·외부 AI/메일/CRM/결제 제공자가 미정인 현재 범위는 로컬 구현과 연결 설정이다.

## 편집·조회·재개

IndexedDB의 미확인 명령은 자동 정리하지 않는다. 브라우저가 저장 공간을 회수할 수 있으므로 저장 사용량·지속 보관 상태, 원본 파일 보존, 확인된 이전 명령만 정리하는 조작을 제공한다. 오프라인에서는 문서 편집만 보관하고 권한·결제·운영 삭제를 실행하지 않는다.

## 실제 관리 기능

| 업무 | 실제 서버 경로와 UI |
|---|---|
| 환경 설정·기능 중지 | `config/changes`의 변경 지문·기준 revision을 검토 후 적용한다. 기능 플래그는 기존 revision·사유·만료를 보낸다. 발행 권한을 확인한다. |
| 추가 인증 | 인증 앱 등록/교체, 등록 코드 확인, 일회용 복구 코드, 같은 세션·method/path·payload·대상에 묶인 일회성 step-up을 제공한다. 비밀번호/코드는 브라우저 저장소에 보관하지 않는다. 조직 수준 기존 API는 프로젝트 범위를 잘못 붙이지 않고, 환경 생성은 원본 운영 환경을 확인한다. |
| 비밀·키 회전 | 비밀 버전 등록·실제 연결 시험·활성화·미사용 버전 폐기, 플랫폼 키 회전 작업의 같은 ID 재개를 제공한다. UI에는 원문 대신 참조·버전·검토 상태를 표시한다. |
| 파일 격리·승인·변형 | 새 업로드는 격리/비공개 상태를 표시하며 승인 전 연결을 차단한다. 출처·사용권·제공 범위·검토 사유를 CAS 승인한다. `blobs/:id/variants`의 실제 서버 픽셀 변환으로 원본 이하 크기의 PNG/WEBP를 만들고, 원본을 보존한 격리된 새 참조를 별도로 승인한다. 직접 만든 변형 파일의 원본·변형 키 업로드도 지원한다. 외부 악성 파일 검사는 미연결로 표시한다. |
| 지원·기계 계정 | 범위·기간·사유를 명시한 지원 세션 발급/폐기, 기계 계정 발급/회전/폐기를 검토 후 요청한다. 토큰은 발급 결과에서 한 번만 표시한다. |
| 워크플로 | 서버의 부작용 없는 simulation 결과를 확인한 뒤 같은 workflow revision·입력 지문으로 실행한다. 미확인 외부 효과는 복구 대사 업무에서 확인한다. |
| 예약 | IANA 시간대·중복 시각/없는 시각 정책을 저장한다. 기존 규칙 수정, 자원 정원/사용 상태, 휴일 추가/제거를 `booking/reviews`로 검토한다. 확정/제안/대기 충돌이나 만료가 있으면 적용을 비활성화한다. 검토 이후 변동은 서버가 CAS로 보류하며 이미 생성한 시각은 보존한다. |
| 사용량·금액 원장 | `usage`의 실제 예산/예약/실사용과 `ledger`의 정수 minor 금액·통화를 조회한다. 실제 operation ID로만 예약 사용량을 대사한다. 주문/구독 원장은 20건 cursor로 조회한다. |
| 저장소 이전·작업 예산 | 선택 환경의 로컬 SQLite 복사본 준비→건수/내용 재대사→쓰기 전환→최신 자료 포함 역복구를 분리한다. 전역 실행 수·종류별 풀·시간/종료 예산은 revision 비교 후 변경한다. 변경은 플랫폼 관리자/로컬 소유자만 가능하다. 외부 DB/클라우드/다중 호스트 이전은 미연결이다. |
| 릴리스·검수 링크 | 고정 산출물 해시·대상 설정 revision·검토 지문을 비교하고 동일 산출물을 승격한다. 검토 이후 기능 플래그·활성 비밀 버전 변경도 다시 검토한다. 인증된 정적 검수 주소를 1–120분 발급하고 발급 세션에서 즉시 폐기한다. 검수 화면의 JS/폼 실행은 차단된다. 로컬 주소는 원격 공유·공개 제공자 배포의 증거가 아니다. |
| 추적·장애 감지 | 선택 환경의 실제 요청 집계·최대 100건 추적·장애/해결 상태를 조회한다. 알림 기준은 CAS·추가 인증으로 변경하고 플랫폼 권한을 확인한다. 외부 OTLP 설정과 실제 수집기 전달 성공을 구분하며 메일/외부 알림 전달은 미연결로 표시한다. |
| 복구·백업·증거·수명주기·catalog | 기존 서버의 실제 목록·검증/복원·증거·인계/보관/폐기·catalog 승인 상태에 연결한다. 동일 범위를 검토한 후 명시적 적용 버튼으로 변경한다. |

목록 요청에는 scope와 요청 순서를 확인하여 늦게 도착한 이전 환경의 결과가 현재 화면을 덮어쓰지 않도록 한다. 변경 검토는 원래 사이트/환경과 입력을 캡처하고 인증 전후에 다시 확인한다. 관리 동작은 서버의 권한·현재 상태 확인을 보안 경계로 사용한다.

## 검증과 남은 경계

`tests/editor-advancement.test.ts`는 안정적인 필드 명령/제거/구조 삽입, 전체 문맥 roundtrip, 조직·환경별 추가 인증 대상, 의미상 참조 충돌을 검사한다. 2026-10-08 기준 6개 통과했다. 편집기·인프라·관련 테스트 ESLint와 프로덕션 빌드도 통과했다.

`tests/system-editor.e2e.ts`는 실제 서버 응답을 유실시킨 ACK 재개, 실제 offline/online 변경 보관, 링크/검색/뒤로 가기, 설정 변경과 실험 집계, 불변 CMS 발행본, 인증 검수 주소/폐기, 예약 영향 검토, 알림 기준, 대형 문서의 검색/키보드/내보내기를 검사한다. 관리형 HTTPS cookie/실제 인증 앱·복구 코드·읽기 권한 의견/실험 배정은 `tests/creator-editor.e2e.ts`에서 검사한다. 기존 시스템 9개·확장 6개·편집기 4개 검사가 통과했고, 관리형 1개는 데스크톱 의견 패널 수정 후 재실행에서 통과했다. 추가한 105건 모델 이전의 배치/활성화·서버 이미지 변형/격리/공개 승인도 실제 브라우저에서 통과했다. 전체 최신 소스의 통합 회귀 결과는 상위 구현 보고서에 기록한다.

대형 편집기 측정은 `.data/system-editor-capacity.json`, `.data/system-editor-capacity-{100,500,1000}.json`과 Playwright 첨부 파일로 기록한다. 테스트 전용 `AUTOMADE_CAPACITY_BLOCKS=100|300|500|1000`으로 크기를 선택한다. 자동화 왕복 지연과 DOM input/keydown timestamp부터 두 번째 animation frame까지의 화면 반영 지연을 따로 기록한다. 각 측정은 15개 표본의 p95이며 Chromium 153, Windows 11, Ryzen 7 4800H·16GB 로컬 환경이다. 화면 밖 선택·전체 원본 내보내기는 모든 측정 크기에서 보존됐다.

| 블록 | 입력→화면 p95 | 키보드→화면 p95 | DOM 요소 | 사용 JS heap |
|---:|---:|---:|---:|---:|
| 100 | 37.5ms | 27.9ms | 1,844 | 37.3MB |
| 300 | 36.2ms | 26.9ms | 4,703 | 47.4MB |
| 500 | 53.8ms | 19.3ms | 7,445 | 44.7MB |
| 1,000 | 54.6ms | 47.8ms | 14,466 | 72.2MB |

이 로컬 fixture에서는 입력·키보드 화면 반영 목표 p95≤100ms를 충족했다. 300블록 값은 2026-10-09 전체 최종 검증에서 다시 측정했으며, 나머지 크기는 직전 선택 검증 기록이다. 자동화 왕복을 포함한 최종 300블록 지연은 각각 119.9ms/124.9ms이며 목표와 같은 지표로 취급하지 않는다. DOM은 크기에 따라 늘어나므로 1,000블록 지원 계약에서 측정된 14,466개를 실제 기준으로 남기고, 장치별 성능 보장이나 무제한 크기 지원으로 해석하지 않는다. 향후 변경의 freeze 회귀 검사(자동화 p95 2초 미만)는 사용자 지연 목표를 대체하지 않는다. CPU/heap 수치는 단일 로컬 fixture이며 장기 실행·운영 환경의 성능을 대신하지 않는다.

최종 `tests/system-editor.e2e.ts`에는 자동 저장을 기다리지 않은 즉시 수정/생성 및 팝업 차단 상황에서 생성 요청 원본이 실제 서버 canonical ACK와 일치하는 검사도 포함했다. `syncProject`의 boolean 계약을 유지하면서 같은 큐에서 확인한 canonical 문서를 생성 요청·감시 revision에 사용한다. 전체 Chromium 42/42와 단위/통합 227/227의 최신 결과는 [최종 검증](verification.md)을 따른다.

실제 스크린 리더·키보드 사용자 평가·물리 모바일 장치, 외부 제공자/수집기/메일/결제의 실연결, 운영 환경 부하·장기 실행·원격 배포는 이 로컬 검증으로 완료됐다고 주장하지 않는다. 브라우저 저장 공간 강제 회수·quota 고갈의 실제 장치 검증도 별도다. 시스템/운영 DB 마이그레이션과 환경 변수는 `docs/database.md`, `docs/security.md`, `docs/deployment.md`의 서버 계약을 따른다.
