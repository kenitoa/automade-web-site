# 편집 원본과 생성 사이트의 고도화 계약

## 원본 호환성

`schemaVersion: 2`를 유지한다. 고도화 필드는 선택적이며 `parseProject`가 목록 개수, 문자열 길이, 수치 범위, URL, ID와 경로를 검증한다. 기존 원본에 `design.themeMode`가 없으면 기존에 저장된 개별 디자인을 사용한다. 새 블록은 사이트 테마의 표면 색상과 모서리를 상속하며 사용자가 직접 지정 모드로 전환할 수 있다. 기존 v1 좌표와 ID를 유지하는 마이그레이션에서는 직접 지정 스타일을 보존한다.

상태 변경은 `commit`으로 revision과 UTC 수정 시각을 갱신한다. 페이지 복제와 섹션 삽입은 새 ID를 만들고 내부 이동, 모달, 폼 완료 동작과 차트의 표 연결을 다시 연결한다. 페이지·블록 삭제는 해당 연결을 해제한다. 저장한 섹션은 원래 페이지를 삭제해도 불러올 수 있다.

## 콘텐츠와 표현

- `settings.brief`: 사이트 목적, 주요 방문자, 주요 행동, 분위기와 사용자가 제공한 자료.
- `theme.typography`, `theme.button`: 공통 글자·간격·너비·버튼 스타일.
- `layout.responsive.tablet/mobile`: 열 수, 간격, 여백, 글자 크기와 제목 크기. 기기마다 시각적 순서만 바꾸지 않고 모든 화면에서 같은 DOM 순서를 사용한다.
- `props.richText`: 문단·목록과 텍스트·강조·안전한 링크. 원시 HTML을 렌더링하지 않는다.
- `props.imageSettings`: 장식용 여부, 비율, 맞춤 방식과 초점. 장식용 이미지의 대체 텍스트는 빈 문자열이다.
- `collections`와 `props.collectionBinding`: 게시 상태·분류·개수에 따른 콘텐츠 목록과 상세 경로. `publishedAt`은 기록용 UTC 시각이며 자동 예약 게시 조건이 아니다.
- `props.chartBinding`: 표의 이름 열과 숫자 열을 연결한다. 생성 사이트에서는 현재 API 데이터와 저장 이벤트를 반영하며 조회 오류와 빈 상태를 표시한다.
- `props.translations`, `Page.translations`, `ContentRecord.translations`, `settings.languages`: 페이지·블록·CMS 문구와 언어 선택. 비어 있는 번역 문구는 원문의 표시를 유지한다. 번역은 사용자가 제공한 내용이며 자동 번역에는 외부 생성 공급자가 필요하다.

반응형 설정과 애니메이션은 공통 런타임을 사용하므로 편집 미리보기와 독립 생성 결과에 함께 적용한다. 움직임 줄이기 설정에서는 등장 애니메이션과 부드러운 스크롤을 중지한다.

## 폼과 표

`formSettings`는 개인정보 안내, 필수 동의, 문의 분류, 제출 완료 문구와 후속 동작을 설정한다. 동의가 필요한 폼은 서버에서도 `values.__consent === "true"`를 검증한다. `__consent`, `__proto__`, `constructor`, `prototype`은 일반 필드 ID로 사용할 수 없다. 미리보기 제출은 운영 데이터를 저장하지 않는다.

표 열은 필수·중복 제한·읽기 전용·숨김·너비·순서를 설정할 수 있다. 숨김은 표시 설정이며 데이터 접근 권한을 대신하지 않는다. `validateTableRows`는 전체 제안 행을 검사하고 기존 읽기 전용 값을 변경하지 못하게 한다. CSV 가져오기는 열 연결과 오류를 미리 보여주고 확인한 후 기존 저장 API를 사용한다. CSV 내보내기는 수식으로 실행될 수 있는 값을 중화한다.

표 저장의 버전 충돌에서는 내 수정과 최신 데이터를 비교하며, 선택한 수정은 최신 버전을 기준으로 다시 검증한다. 관리 권한이 있는 운영자는 변경 이력의 버전·시각·수정자·변경 전후를 확인하고 이전 이력을 추가로 조회할 수 있다. 이력 열람이 운영 데이터를 자동으로 복원하지 않는다.

## 공개 경계와 회원

`publicProject`는 숨김 블록·비공개 페이지·그 하위 블록, 초안 콘텐츠, 사용하지 않는 이미지, 기획 자료, 검토 체크리스트와 저장 섹션을 공개 HTML에서 제외한다. `Page.access: "members"`의 제목·주소는 로그인 안내와 메뉴를 위한 공개 정보이다. 실제 본문·설명·번역·이미지는 공개 응답에서 제외한다. 회원 컬렉션의 레코드도 제외한다.

`memberProject`는 서버가 계정을 인증한 이후에만 반환한다. 회원 API도 비공개·숨김·초안과 편집 전용 정보를 반환하지 않는다. 로그인 후 런타임은 인증된 원본을 조회하고, 로그아웃하면 메모리의 회원 콘텐츠를 제거한다. 이전 회원 조회 요청이 로그아웃 후 늦게 도착해도 내용을 다시 표시하지 않는다. 클라이언트의 로그인 안내와 버튼 숨김은 보안 경계가 아니며 서버 인가가 필수이다.

생성 서버의 실제 API를 사용하는 계정·주문·예약 화면은 미리보기에서 거래를 만들지 않는다. 가격·재고·정원은 서버 데이터로 표시하고 실제 저장 결과를 기다린다. 외부 결제 서비스 이동이 결제 완료를 뜻하지 않는다. 결제 완료는 서버가 공급자의 결과를 검증해야 한다.

매진된 미래 일정에는 `대기 신청`을 제공한다. 로그인한 방문자는 자신의 대기 목록, 제안 수락 기한, 확정 예약 번호, 취소·만료 상태를 확인할 수 있다. `/api/platform/bookings/waitlist`와 자신의 항목에 대한 `accept`/`cancel`을 사용하며, 30초 주기 및 명시적인 새로고침으로 운영 작업이 발행한 실제 제안을 확인한다. 조회 실패·로딩·빈 상태를 별도로 표시하고 로그아웃하면 대기 자료와 늦은 조회 응답을 제거한다. 수락 기한이 지나면 화면에서 수락 버튼을 제거하며 서버도 만료·소유권·정원을 다시 검증한다. 대기는 이메일 발송이나 예약 확정을 뜻하지 않으며 방문자의 수락 후 실제 예약이 생성되어야 확정이다. 현재 서버는 동일 계정·일정에 종료된 대기 기록도 보존하므로 같은 일정의 재신청을 제공하지 않는다.

## 검색·공유와 품질

`Page.seo`, `settings.siteUrl`로 검색·공유 제목, 설명, 공유 이미지, HTTPS 대표 주소와 검색 제외를 설정한다. 생성 시 게시된 CMS 상세 HTML, sitemap과 robots 문서를 함께 만든다. 초안·비공개·회원 자료와 검색 제외 페이지는 sitemap에 포함하지 않는다. 검색 제외는 접근 권한 설정을 대신하지 않는다.

서버의 `/sitemap.xml`과 `/robots.txt`는 최신 `project:cms` 발행 스냅샷을 읽는다. 초기 HTML의 20개 레코드 제한을 사이트맵에 적용하지 않으며, 공개된 모든 CMS 상세와 설정된 언어별 대표 주소를 포함한다. URL이 10,000개를 넘으면 루트 문서는 sitemap index가 되고 `/sitemaps/1.xml`부터 페이지별 XML을 제공한다. 없는 페이지는 404이며 HEAD도 지원한다. 독립 정적 내보내기·재빌드도 모든 URL의 같은 인덱스와 페이지 파일을 생성한다. XML 이스케이프와 분할은 [공식 sitemap 규격](https://www.sitemaps.org/protocol.html)을 따른다. 서버 응답은 `no-store`여서 발행 취소가 다음 조회부터 반영된다.

기본 언어는 기존 `/`, `/cases/first` 주소를 유지하며 추가 언어는 `/en/`, `/en/cases/first`와 같이 언어 접두사를 사용한다. 언어 선택은 현재 페이지·CMS 상세 경로를 유지하고 주소·canonical·hreflang·문서 언어·제목·설명을 함께 바꾼다. 화면 안에서 페이지나 언어를 바꿀 때 공유 이미지와 JSON-LD의 제목·설명·대표 주소·언어도 갱신하며 이미지가 없는 화면으로 돌아오면 이전 공유 이미지를 제거한다. 직접 열기와 새로고침에서도 같은 언어의 HTML을 서버에서 제공한다. 언어 접두사와 충돌하는 원본 페이지·별칭·컬렉션 경로는 검증에서 거부한다. `siteRoutes`는 원본으로부터 회원 CMS의 게시된 상세 주소도 열거하지만 `html`은 공개 투영을 적용해 로그인 안내만 출력한다. 이 주소는 `noindex`이며 회원 본문·레코드 제목·번역·이미지는 공개 HTML/JSON에 포함하지 않는다.

품질 문제는 위치·필드·영향·해결 방법·검사 방식을 제공한다. `previewQualityFix`는 실제 측정 가능한 대비와 넘침, 이미 저장된 이미지 대체 텍스트, 역전된 입력 범위에 한해 검토할 수정안을 만든다. 대비는 캔버스·상위 블록 배경과 글자의 알파 합성을 반영한다. 원본은 바꾸지 않으며 잠긴 대상·없는 대상·추측이 필요한 문구나 연결은 자동 수정하지 않는다.

AI 수정에는 `minimizeProposalProject`와 `mergeProposal`을 사용한다. 공급자에게 실제 운영 행·이미지·CMS 자료·기획과 검토 메모·동작 URL·개인정보 안내를 보내지 않는다. 선택 영역 밖의 문구도 제거한다. 응답은 작업별 허용 필드에만 반영하며 페이지 접근 권한·게시 상태·폼 검증 규칙·가격·데이터·이미지·연결·잠금과 원본 구조를 보존한다. 적용 전 비교와 실행 취소는 필수이다.

## 검증 범위

추가 단위 테스트는 원본 호환성, 입력 경계, 콘텐츠 공개 경계, 검색 문서, CSV, 표 제약, 차트 연결, 복제·섹션, 동의, 안전한 본문, AI 수정 범위와 품질 수정안을 확인한다. `tests/runtime-upgrade.e2e.ts`는 별도의 생성 사이트를 실행하여 회원 공개 경계와 로그아웃, CMS 경로, 언어·모바일 레이아웃, 문의 동의, 주문·예약·취소, 표 제약·충돌·변경 이력을 브라우저에서 확인한다.

`tests/expansion-domain.test.ts`는 10,004개 언어별 공개 URL의 누락 없는 분할과 비공개 제외를 확인한다. `tests/expansion-runtime.e2e.ts`는 35개의 공개 CMS 자료, 초안과 회원 자료를 가진 독립 재빌드 서버에서 20개 밖의 상세·사이트맵과 언어별 주소, 발행 취소 즉시 반영을 확인한다. 실제 매진 예약의 대기 신청·취소, 운영 서비스의 제안 발행, 방문자의 수락으로 예약 생성, 만료된 수락의 서버 거부와 로그아웃 후 대기 자료 제거도 확인한다.

브라우저의 모바일 너비 검증은 실제 휴대전화 또는 스크린리더 검증을 대신하지 않는다. 실제 메일·CRM·AI·결제 공급자의 운영 응답, 외부 도메인의 HTTPS와 실제 공개 배포는 각각 연결된 환경에서 별도로 검증해야 한다.
